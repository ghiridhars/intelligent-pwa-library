# Local Development Setup

## Prerequisites

| Tool | Version | Install |
|---|---|---|
| Flutter | 3.x (stable) | https://docs.flutter.dev/get-started/install |
| Dart | 3.x (bundled with Flutter) | — |
| Python | 3.10+ | `sudo apt install python3 python3-pip python3-venv` |
| Tesseract | 4.x | See [OCR Pipeline](ocr-pipeline.md#installation) |
| Git | any | `sudo apt install git` |

Verify Flutter is ready:
```bash
flutter doctor
```
All required checks must pass. The "Chrome" check is needed for web development.

---

## 1. Clone and install dependencies

```bash
git clone https://github.com/username/library-manager.git
cd library-manager

# Flutter packages
flutter pub get

# Python packages (for OCR scripts — optional if not running OCR locally)
python3 -m venv library_env
source library_env/bin/activate
pip install -r scripts/requirements.txt
```

## 2. Running the web app locally

Flutter's development server only serves the Flutter app — it does not serve `data/` or `raw_assets/`. You need a second server at the project root to make those available.

**Terminal 1 — static file server (project root):**
```bash
python3 -m http.server 8000
```
This serves `data/catalog.json`, book indices, and PDFs at `http://localhost:8000/`.

**Terminal 2 — Flutter web:**
```bash
flutter run -d chrome --web-port 5000
```

When the app fetches `data/catalog.json`, it uses `Uri.base` which resolves against `http://localhost:5000/`. This means the fetch goes to `http://localhost:5000/data/catalog.json` — **not** the Python server on port 8000.

To make this work during development, either:

**Option A (simplest):** Run Flutter web from port 8000 too:
```bash
# Stop python3 -m http.server 8000 first, then:
flutter run -d chrome --web-port 8000
```
Now `Uri.base` is `http://localhost:8000/` and `data/catalog.json` is served by the Flutter dev server (which falls back to the filesystem for unknown paths).

**Option B:** Temporarily override `AppConfig.resolveUrl` to use `http://localhost:8000/` as the base during local development.

> **Note**: For day-to-day UI development (no data changes), Option A is the cleanest. Only restart the Python server if you need to test PDF loading from `raw_assets/`.

## 3. Running on iOS (macOS required)

```bash
# List available simulators
flutter emulators

# Start a simulator
flutter emulators --launch apple_ios_simulator

# Run
flutter run -d iPhone
```

For a physical device, connect via USB and trust the computer. An Apple Developer account is **not** required for development builds — only for TestFlight or App Store distribution.

Before running on iOS, update `lib/config.dart` with your local server URL or GitHub Pages URL so the app knows where to fetch data from:
```dart
static const String githubPagesUrl = 'http://localhost:8000';
```

---

## 4. Running on Android

```bash
# Start an emulator
flutter emulators --launch Pixel_8_API_35

# Run
flutter run -d emulator-5554
```

For a physical device, enable Developer Options and USB Debugging, then connect via USB.

Same note as iOS: update `lib/config.dart` with your data server URL for local testing.

## 5. Hot reload and hot restart

- **Hot reload** (`r` in terminal or save file in IDE): rebuilds the UI tree without restarting the app. State is preserved.
- **Hot restart** (`R` in terminal): full restart, state is reset. Use this after changing `main()`, `initState()`, or Hive initialisation.

## 6. Project-level configuration to update before building

These values must be personalised before any production build or deployment:

| File | Setting | What to put |
|---|---|---|
| `lib/config.dart` | `githubPagesUrl` | Your GitHub Pages URL, e.g. `https://username.github.io/library-manager` |
| `.github/workflows/build-index.yml` | `--base-href /library-manager/` | Replace `library-manager` with your actual repo name |
| `web/admin/index.html` | `repo: "username/library-manager"` | Your GitHub username and repo name |
| `web/admin/index.html` | `client_id: "YOUR_GITHUB_OAUTH_CLIENT_ID"` | From your GitHub OAuth App settings |

## 7. Folder structure reference

```
lib/
  main.dart             App entry — Hive init → runApp
  app.dart              Router + AppServices (InheritedWidget)
  config.dart           URL resolver — update githubPagesUrl here
  models/               Book and Song data classes
  screens/              LibraryScreen · BookScreen · PdfScreen
  services/             CatalogService · CacheService · SearchService

data/
  catalog.json          Edit to add books (or use Decap CMS)
  indices/              Generated by ingest.py; review before committing

raw_assets/             Add PDFs here via git (not via CMS)
scripts/
  ingest.py             Run this locally after adding a new PDF
web/
  admin/index.html      Decap CMS config
  index.html            Contains PDF.js CDN scripts
```

## 8. Running tests

```bash
flutter test
```

The smoke test in `test/widget_test.dart` verifies `LibraryApp` mounts without errors. It does not make network requests — data loading is tested via the FutureBuilder error state in the running app.
